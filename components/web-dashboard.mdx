The web dashboard is built with C# and ASP.NET Core 8 MVC and is used by logistics operators at Scanmex headquarters. From a single browser interface, operators can import pending orders from SAP Business One, assemble and sequence them into driver routes, and watch every active vehicle move across a live Google Maps view as deliveries are completed throughout the day.

## Daily workflow

<Steps>
  <Step title="Open the dashboard and log in">
    The logistics operator opens the web dashboard in a browser and authenticates with their credentials stored in SQL Server.
  </Step>
  <Step title="Import pending orders from SAP Business One">
    The operator triggers a pull from the SAP Business One Service Layer, which returns all open sales orders via the OData v4 API and loads them into the dashboard.
  </Step>
  <Step title="Assign orders to drivers, creating sequenced routes">
    Orders are selected and assigned to a specific driver. The dashboard saves a sequenced route record — each stop is numbered and tied to a delivery address.
  </Step>
  <Step title="Monitor the live map as drivers begin their rounds">
    As drivers start moving, the Android app broadcasts GPS coordinates every few seconds. The dashboard map updates in real time so the office can see each vehicle's current position.
  </Step>
  <Step title="Confirm all deliveries are marked complete at end of day">
    The operator reviews the delivery monitoring panel to verify every stop has been confirmed. Any unconfirmed stop is flagged for follow-up before the day closes.
  </Step>
</Steps>

## Tech implementation

<Tabs>
  <Tab title="Backend (C#)">
    The server side is built on ASP.NET Core 8 MVC. **Controllers** handle all route logic: they receive HTTP requests from Razor views, validate input, execute SQL queries against SQL Server, and dispatch OData v4 calls to the SAP Business One Service Layer. **Models** map directly to the SQL Server tables that store routes, stops, drivers, and delivery confirmations. When a route is saved or a delivery confirmed, the controller also sends the corresponding update to SAP so the ERP stays consistent without any manual re-entry.

    <Note>The snippet below is an illustrative skeleton showing the pattern used by route controllers. It is not a copy-paste runnable excerpt.</Note>

    ```csharp RouteController.cs
    [HttpPost]
    public async Task<IActionResult> AssignRoute(int driverId, List<int> orderIds)
    {
        // 1. Validate driver exists in SQL Server
        // 2. Insert route record with sequenced stops
        // 3. Call SAP Service Layer to update order status
        return RedirectToAction("Index");
    }
    ```
  </Tab>
  <Tab title="Frontend">
    Each screen is rendered by a **Razor view** (`.cshtml`), which combines C# model data with standard HTML markup served from the MVC framework. **JavaScript** powers the Google Maps integration: it initialises the map, draws route polylines, and polls the server for updated driver coordinates to animate vehicle markers in real time. **CSS3** handles all visual styling — layout, colour tokens, hover states, and responsive breakpoints — without any external CSS framework dependency.
  </Tab>
</Tabs>

<Note>
  The dashboard shares the same SQL Server database as the Android app. When a driver confirms a delivery on the Zebra terminal, the record is written directly to SQL Server and appears in the dashboard immediately — there is no synchronisation delay between the two applications.
</Note>
